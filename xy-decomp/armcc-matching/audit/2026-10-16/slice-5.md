## (c) FLAGGED -- cannot be made natural (known tricks, must stay tagged)

- **`trick(volatile)`, 34 files** (all GetMgr script-handler callers that read `args[1]` and narrow it): the arg pointer is `volatile int *`. Retail loads the whole word (`ldr`) and narrows afterwards (`uxth` / `sxth` / `sxtb` / `and #255`, or stores the full word with `strb`) before the `bl GetMgr`; non-volatile armcc folds the narrowing into `ldrh`/`ldrsh`/`ldrb` and loads late. Each of the 35 volatile files was recompiled with `volatile` stripped: 35/35 fail. Also tried on 0x5c5d4 (non-volatile): callee taking `unsigned char`, `(unsigned char)x` through a local, `& 255` through an `unsigned *` and through a local; all still emit `ldrb`. Additional required locals (each verified by removing it): 0x5cfc8 (second volatile on the chain load pins `mov r1,r4` after the chain), 0x9484c / 0x928ac / 0x94894 (`t`/`tab`/`i` order locals; 0x9484c also the halfword pointer `p`), 0x98b84 (`m`/`v`/`t`), 0x93d10 (`t`, `q`), 0x9515c (`u`/`t`/`c`).
- **`trick(volatile-load)`, 0x9aeb8**: retail is `ldrh` + `and #15` of a halfword field; armcc narrows to `ldrb` for a plain u16 read, for a u16 local, and for 4-bit / 28-bit bitfields (all tried), so the field read goes through `volatile unsigned short *`. Its sibling 0x9af9c (`>> 4`) is natural.
- **`trick(redundant-local)`, 0x94ce4**: `int q = o ? o->+404 : o;` keeps self in r4 / mgr in r5; the plain `if (o) V(o->+404)` form was tested and fails (register swap).

No `asm`, intrinsics, `#pragma`, `register`, `goto`, `__attribute__` or `.cpp` appear anywhere in the slice. Nothing was flagged for anything but the three constructs above.

## (d) Patterns / lessons

- **Kind naming was split**: the same arg-narrowing volatile lever carried two names (`volatile` and `volatile-load`) inside this slice (28 files used `volatile-load`). README defines `volatile` = arg read through `volatile int *`, `volatile-load` = field/load kept from being narrowed/dropped, so the 28 arg cases were normalised to `volatile` and only 0x9aeb8 (a field read) keeps `volatile-load`. The README table's "files tagged" column should be re-derived (`grep -rl 'Style: trick(volatile)'`; now 34 in DllField slice 5 alone vs "~14").
- **Unused externs were common**: 25 files carried copy-paste declarations of unrelated helpers (`F`, `K3`, `G`, `Sink`, a duplicated `GetMgr`/`Helper` pair). They are dead code and were deleted (no codegen effect, verified).
- **Redundant locals found only once**: 0x5e068 compiled with `m`/`t` dropped (volatile still needed). By contrast the "read the args into locals first, then call GetMgr()" shape (0x9b950, 0x9be50, 0x5db64, 0x95130, 0x9876c-family, 0x5d0f0, 0x5d45c, 0x9d214) is required for the retail load order (inline forms fail); I kept it natural because reading script args up front is ordinary code, but it is the same load-order pressure as `ordering-local`; if the README wants a stricter line, those ~20 files would move to `trick(ordering-local)`. 0x91094 compiles identically in a nested-call form (`v`/`w` temporaries are not needed) but the named temporaries are ordinary and left as is.
- **0x916dc**: the `q = m + 124` local is not a trick: retail addresses the cleared word as `r4+24` from an embedded sub-object at +124, so `q` is the placeholder for that sub-struct pointer. Kept natural, header now says so.
- **Families**: the `pad[N]` struct getters (0x74dc8..0x74e18, 0x7f60c..0x7f678) and the `Sink`/`Tail` pointer-chain thunk family are plain and stay natural (weak evidence: tiny leaf shapes compile identically however written).
- **Tooling gotchas for auditors**: a worktree has no `.Data/` (gitignored), so set `XY_ROMFS` to the main checkout's `.Data/Raw_Extracted/romfs` (absolute); the shared scratchpad is shared by all auditors, so use a private subdirectory (another auditor overwrote a generic `ver.py` mid-run). Jump-table files mention `DllField <other offset> ...` (jumptable_relocs) in their headers, so a naive "first DllField 0x.. 0x.." regex picks the wrong offset.
